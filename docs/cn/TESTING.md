# 功能测试指南

自行构建并安装 App 后，可按以下步骤检查连接、录音、语音问答和通知。已测试的设备与系统见[兼容性](COMPATIBILITY.md)，版本结果见[测试记录](AUDIT.md)。分享结果时请记录提交号和设备环境，并对录音、问答、通知及日志脱敏。

## 前提

先完成 [首次配置](BUILDING.md)：填写眼镜蓝牙地址、授予蓝牙权限、按需完成系统配对；配置自己的服务 Key 并打开“实时识别，边说边显示提问”。通知默认处于“仅监听检查”，确认手机正常提醒后才关闭该开关。不要反复恢复出厂设置。

本地录音不需要云 Key。实时 ASR 和模型问答会使用配置的服务；只在准备好上传测试语音时进行。手机“上传预置语音”按钮依赖未附带的开发样本，干净安装不支持；改用“选择音频上传转写”并明确选择自己的测试文件。

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 连接与待命 | 保存配置，连接，等 App 报告待命 | 实际认证成功且待命就绪；仅蓝灯闪烁不是连接成功 |
| 本地录音 | 录音页开始，说 10–20 秒，再结束并保存、播放 | 手机有可播放文件，语音清晰、长度合理；记下进度条异常；不上传云端 |
| 实时语音 | 唤醒眼镜，问一个简短问题 | 说话期间提问逐步出字，结束后眼镜出现回答 |
| 连续两轮 | 第一轮答案出现时再唤醒，问不同问题 | 无需点手机即可接收第二轮，提问/回答对应且无前轮结果覆盖 |
| 熄屏 | 手机熄屏静置一分钟，再唤醒眼镜提问 | 持续收音、逐步显示文字并回答，无闪退；一分钟不代表整夜可靠性 |
| 通知 | 授权、选应用、开总开关；先仅监听确认手机正常，再关闭仅监听，用所选应用收新消息 | 手机照常提醒，眼镜收到完整消息；每条消息独立编号，突发排队仍待优化 |
| 可选知识库 | 配置专用 Gateway 后提问 | 回答到眼镜；手机来源与服务端结构化 sources 一致；空 sources 不证明检索过资料 |

## 空闲检查

待命就绪且没有正在进行的录音/问答，约定三分钟不唤醒、不按按钮、不在 App 发起请求。在已配置 ADB 的根目录运行：

```powershell
python idle_check.py --serial "替换为手机序列号" --seconds 180
```

工具采集开始和结束两份快照，对比同一会话的录音请求、音频包、云上传、业务提交、实时云连接累计计数及待命状态。`passed` 表示检查范围内计数未增长。如果会话发生变化或计数增加，需要结合期间的操作和日志排查；主动唤醒后请重新开始空闲检查。

输出保存在 `out/power-tests/`，包含原始状态，分享前请脱敏。此工具检查 App 计数器，不测量蓝牙流量、实际电流、云账单或厂商 SDK 心跳；长期耗电需另行测量。

## 留存方式与已知经验

每项记录：日期、候选版本/哈希、手机型号与系统、固件（未知就写未知）、前提、操作、协议结果、佩戴者观察、是否调用云端、异常及脱敏证据。使用 [观察台](OBSERVER.md) 辅助，但不要把模拟渲染当成真实镜片确认。

已遇到的问题包括首次缺地址、默认未启用实时 ASR、通知仅监听不转发、后台系统限制、答案显示时续问时序，以及熄屏收音退出。测试必须覆盖这些条件；不要用反复配对替代定位。通知变慢/突发排队、长录音、长期耗电及杀进程/重启恢复仍需要专项验证。涉及诊断入口或会话生命周期的改动还需验证 App 内部连接正常，以及失败/重复实例不会清理现有会话；安全机制见[安全说明](SECURITY.md)，验证状态见[审核索引](AUDIT.md)。
