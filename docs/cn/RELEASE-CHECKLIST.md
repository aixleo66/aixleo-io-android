# 分发范围与版本交付检查

本文是可重复使用的维护清单，随分发内容或流程变化更新。每次检查的实际结果、代码提交与产物哈希写入[审核记录](AUDIT.md)，不在所有使用文档中重复维护版本状态。

## 当前源码分发范围

包含自有 App/适配源码、测试、构建脚本、空配置模板，以及固定的 `vendor-payload.jar`（三份官方 DEX、两份协程服务声明）、Java-WebSocket/SLF4J 依赖与许可、Turbo IO 参考及来源说明、PolyForm 许可原文。使用说明覆盖首次配置、观察台、回归测试、实验性 Gateway 和兼容性。

不包含预编译 APK、`artifacts/` 安装包、完整官方 APK、私人签名、Key/Token、真实本地配置、录音、真实问答与通知、设备唯一标识、个人知识库、Rokid Harness 服务端、原始抓包/全量反编译输出、工具缓存或依赖私人样本的历史 `stream_smoke.py`。

源码推送、创建版本标签和发布 GitHub Release 是不同动作。当前交付范围为源码；后两项在明确安排对应发布时单独执行，不因文档中出现版本号而自动发生。

## 每次交付的检查

1. 确定提交、分发清单和版本差异，补充[变更记录](CHANGELOG.md)。只修改行为受到影响的中英文指南。
2. 检查源文件及嵌套 payload 的凭据模式、排除项、许可原文、来源通知和本地链接。
3. 核对工具链/厂商依赖的固定版本与哈希；代码或构建输入改变时重新运行适用的构建与测试。新快照应生成自己的清单，不修改旧快照的哈希。
4. 记录自动检查、真机结果和未验证项。仅文档变化可做链接、示例及事实一致性检查，但不能增加真机通过结论。完整流程见[测试指南](TESTING.md)。
5. 更新[审核索引](AUDIT.md)并保留历史证据。核实推送或发布实际结果后再记录完成；不把待办写成已完成。

安全设计及调试边界见[安全说明](SECURITY.md)。厂商再分发授权及完整逐文件权属审查尚未完成；附依赖、注明非商业用途或保留 iOS 致谢均不等于取得第三方授权，见[许可范围](LICENSING.md)。文档分工和历史记录规则见[文档维护](DOCUMENTATION.md)。
