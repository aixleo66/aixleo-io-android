# Aixleo iO Android

适配 RayNeo iO 的非官方 Android 伴侣应用与实验性 SDK。

面向开发者的雷鸟 iO 互操作研究项目，附带 Android 示例客户端，用于研究眼镜连接、语音输入、文字显示、录音归档和手机通知转发。

**参考与致谢：本项目在开发过程中参考了 [Turbo1123/Turbo-IO](https://github.com/Turbo1123/Turbo-IO) 的 iOS 实现与研究文档，包括设备通信与会话、语音助手交互、普通录音及显示观察思路。感谢原作者和贡献者的研究工作。** 本项目为单独维护的 Android 研究实现，不是 Turbo IO 作者发布或认可的官方 Android 移植版，也不宣称所有实现均为独立原创。具体引用、移植和许可范围见 [来源记录](PROVENANCE.md)。

**项目与雷鸟及其关联公司无官方隶属、合作或背书关系。RayNeo / 雷鸟 iO 名称仅用于说明兼容设备。** 当前为实验性开发版本，尚未形成稳定的独立 SDK API，不承诺替代官方 App 的全部功能。

使用者需要具备 Android 开发与调试能力，自行准备工具链、签名和服务配置。当前设备通信实现仍依赖特定版本的厂商组件；厂商组件与原创代码的许可范围分开处理。具体要求见 [构建与依赖](BUILDING.md) 和 [第三方说明](THIRD_PARTY_NOTICES.md)。

本源码预览包含示例源码、测试和文档，以及 `vendor/rayneo-venus-1.0.2-68/vendor-payload.jar`：其中为官方 App 三份原样 DEX 与两份协程服务声明。厂商代码单独列明来源，不宣称为本项目原创或由根许可证授权。不提供预编译 APK、完整官方 APK、签名私钥、服务凭据或用户数据。

**已带固定厂商依赖，不需要使用者再次提取。** 使用者自行准备工具链和签名，构建所选提交后安装测试。它不是不依赖厂商代码的独立实现，也没有自动支持其他版本的保证。安装、配置和构建方法见 [构建与依赖](BUILDING.md)。

## 功能与历史验证范围

下表概述已实现的功能及限制。真机证据对应的版本和设备见[兼容性记录](COMPATIBILITY.md)，当前提交的验证状态见[审核索引](AUDIT.md)；历史通过不自动覆盖后续改动。

| 功能 | 状态与限制 |
| --- | --- |
| 设备连接 | 自有设备配对、认证、保存设备后重连；打开 App 自动尝试连接和语音待命 |
| 眼镜语音助手 | 眼镜唤醒、眼镜麦克风收音、实时转写逐步上屏、模型回答显示；连续问答与熄屏问答有真机结果 |
| 普通录音 | 手机开始/结束眼镜录音，保存原件及 WAV、手机播放；当前每段五分钟上限，长时边界尚未完整验收 |
| 手机通知 | 用户授权后按应用选择转发，每条通知独立编号；飞书真实通知已验证，其他应用须分别验收 |
| 实验性远端问答 | 仅保留 Android 连接适配，不附 Rokid Harness 服务端；这是连接本地 Codex 的一种探索方式，本版尚未充分验证其可用性与稳定性，更多接入方式仍在探索 |
| 浏览器观察 | USB 读取 App 协议状态并重绘文字；不是镜片截图，也不是完整历史归档 |

雷鸟 iO 在本项目中用作麦克风输入和眼镜显示终端，不具备本项目可用的摄像头或扬声器能力。语音识别和模型回答由配置的外部服务处理，不声称在眼镜上运行大模型。

## 数据与费用

- 普通录音默认保存在手机，不自动上传转写。
- 语音助手在眼镜唤醒并进入收音流程后，将本轮音频发送到配置的 ASR；有效文本再发送给所选问答服务。误唤醒也可能产生调用。
- 待命不维持持续 ASR 上传。已有三分钟无操作采样未见新增录音、转写或模型任务，但不代表零耗电或永不误唤醒。
- 手机通知转发不调用模型；通知正文可能出现在眼镜和诊断预览中。
- 使用者配置自己的 Key 和服务，相关调用按服务商规则计费。本项目不附带共享额度或维护者的服务账户。

详情见 [权限、数据与诊断](PRIVACY.md)。

## 连接前须知

仅对你拥有或获得明确授权使用的设备进行连接。从官方 App 切换时，可能需要处理原有绑定；官方解绑可能删除眼镜数据并恢复出厂，操作前请阅读设备提示并自行备份。不要将恢复出厂作为日常重连步骤，也不要同时让两个客户端抢占同一设备。

通过手机 App 启动和连接。`lab.py run --execute` 会因诊断入口不导出而拒绝执行，不安装或操作手机；已启动会话的观察与命令工具仍可能读取状态、发送消息或调用云服务，运行前阅读参数及作用说明。

## 项目结构与开发方向

当前代码仍以 Android 示例 App 为中心。下一步逐步分离连接/传输、会话、录音、显示和模型适配接口，使纯逻辑能独立测试。不能将计划中的模块化描述为已完成的 AAR SDK。

## 开发方式与问题反馈

本项目由维护者与 Codex 协作，以 vibe coding 的方式逐步开发和验证。代码、文档和测试覆盖都可能存在问题或遗漏，欢迎大家在使用中帮助发现和改进。

目前已在此前的真机实验中跑通连接、语音问答、录音和通知等核心流程，但这不代表所有细节交互和异常场景都已完善，仍可能存在逻辑错误。我们正在围绕这些细节进行专项测试，并持续迭代后续功能。新改动的自动检查和真机验证状态以[审核记录](AUDIT.md)为准；“代码已修复”不等于“所有场景已通过”。

如果遇到 Bug、兼容性问题、文档遗漏，或有功能建议，欢迎提交 [GitHub Issue](https://github.com/aixleo66/aixleo-io-android/issues)。如果你已有维护者的其他联系方式，也欢迎直接交流。
