# 0.2.1 source build and validation · 2026-09-26

This record separates source-build verification from delivery checks. No APK, signing identity or personal raw logs are distributed. This review did not install the app or add wearer acceptance.

## Source-build baseline

- An independent source copy ran 273 offline tests: 272 passed, with one optional real-audio test skipped. The sdk-lab build, signature and APK alignment checks passed.
- Version 0.2.1 / 2001, application ID dev.xr.rayneo.sdklab. That locally test-signed APK had SHA-256 `b7bc922fbc45cf77ddeda4e1942c7e0002951e03a6548da5dd1af6bbb7fd9284`. Other signatures/later builds need not share its hash.
- Vendor payload entries matched the fixed input; see [third-party notices](../THIRD_PARTY_NOTICES.md).

## Delivery review

- After tool fixes, a clean validation copy ran **277 tests: 276 passed, one optional real-audio test skipped**. Four profile/refusal-order regressions were added after the build baseline above. This run did not rebuild an APK; the APK hash above identifies that earlier build, not a byte-identical rebuild of the final delivery.

- Android business logic matches the current 0.2.1 baseline. Public cleanup changes comments, device identifiers in comments/test fixtures and version-description text, not Android behavior.
- Observer, idle sampler and computer model probe now default to sdk-lab; explicit daily remains available. The model probe refuses the disabled legacy delivery path before calling the cloud. Regression cases cover default/explicit profiles and refusal order.
- Updated building/signing/installation and service setup, weather/background privacy, Gateway retrieval events, developer capability map and bilingual navigation. Both source and documentation are hashed.
- `python verify_source.py --distribution` verifies files and unexpected extras without Git. It does not independently authenticate a manifest; obtain the hash from a trusted delivery channel.

## Not covered

A fresh machine downloading all tools, new installation/wearer acceptance of this delivery, wider phones/firmware, long recordings, all-day background behavior and a complete vendor-binary security audit were not performed here. Old diagnostic/UI limitations remain; see [troubleshooting](../TROUBLESHOOTING.md). [Feature limits](../FEATURES-0.2.1.md) describes device evidence. Passing automated tests is not acceptance of every device capability.

- Added full English feature, device-capability and troubleshooting pages; checked bilingual navigation, parameters and known limits. Chinese and English READMEs contain their corresponding upgrade images.
- Notification documentation separates the new 0.2.1 foreground-service criteria from existing ongoing, group-summary and silent filters. It retains the observed missed notice and unconfirmed cause, without claiming all persistent notices are blocked.
- The final source was tested again in an isolated directory: 277 offline tests, 276 passed and one optional test requiring user-supplied real audio skipped. All 109 Android Java files match the 0.2.1 development baseline after excluding comments and whitespace.
