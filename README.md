# Aixleo iO Android

**雷鸟 iO 的非官方 Android SDK，附带可自行构建的安卓示例 App。** 希望让开发者在眼镜录音、语音助手、文字显示和消息通知等方向做更多尝试。

项目参考了 [Turbo1123/Turbo-IO](https://github.com/Turbo1123/Turbo-IO) 的 iOS 实现与研究文档，感谢原作者及贡献者的分享。Android 版本单独维护，具体参考关系见[来源与致谢](docs/cn/PROVENANCE.md)。

目前属于实验性质，SDK 接口尚未稳定，代码仍以示例 App 为中心，暂未提供独立 AAR。项目与雷鸟官方及 Turbo-IO 作者无隶属或背书关系，仅用于非商业研究与学习。

## 已实现的基础功能

| 功能 | 说明 |
| --- | --- |
| 设备连接 | 配对、认证、保存设备后重连；打开 App 自动尝试连接和语音待命 |
| 眼镜语音助手 | 使用眼镜麦克风收音，实时转写逐步上屏，并显示模型回答；已跑通连续问答和手机熄屏问答 |
| 录音 | 在手机开始、结束眼镜录音，保存原始音频和 WAV，并在手机播放；当前每段上限五分钟 |
| 手机通知 | 授权后选择需要转发的应用，每条通知独立显示；已测试飞书通知 |
| 浏览器观察台 | 通过 USB 读取 App 状态、重绘发送到眼镜的文字，方便开发调试 |
| 实验性知识库接入 | 提供 Android 侧 Gateway 适配，探索连接电脑端 Codex 与知识库；需要自行准备兼容服务端，稳定性仍在测试 |

雷鸟 iO 在这里承担麦克风收音和文字显示，语音识别与问答由你配置的外部服务处理。项目不使用摄像头或扬声器。观察台展示的是协议内容重绘，实际镜片效果仍需佩戴确认。

## 开始使用

当前提供源码和构建说明，暂不提供安装包。仓库已包含构建所需的固定厂商通信依赖，无需再次提取；依赖版本与来源见[第三方说明](docs/cn/THIRD_PARTY_NOTICES.md)。

1. 准备雷鸟 iO、Android 12 及以上手机，以及 Windows x64 开发环境，按[构建与首次配置](docs/cn/BUILDING.md)生成并安装 App。其他手机系统和固件的测试情况见[兼容性](docs/cn/COMPATIBILITY.md)。
2. 在 App 填写眼镜蓝牙地址、授予权限并连接。目前需要手动填写地址，尚无扫描点选设备的界面。
3. 连接后可先测试本地录音。语音助手需要配置你自己的 ASR 和模型服务 Key；通知转发需要另外授予通知使用权并选择应用。

从官方 App 切换时，解绑可能清空眼镜数据并恢复出厂，请先备份并阅读设备提示。日常重连无需反复恢复出厂，也应避免两个客户端同时连接同一副眼镜。

## 数据与费用

- 普通录音保存在手机，不自动上传转写。
- 语音助手唤醒后会向所配置的 ASR 上传音频，并把有效提问发送给问答服务。实时模式边收音边上传；误唤醒也可能产生调用。
- 待命期间不持续上传 ASR 音频；长期功耗和误唤醒仍在测试。
- 手机通知转发不调用模型，但正文可能出现在眼镜和观察台中。
- 云服务使用你自己的账户，按服务商规则计费。取消不能撤回已上传的数据，也不一定能终止远端已接受的任务。

详细的数据去向和权限设置见[隐私说明](docs/cn/PRIVACY.md)。当前为调试构建，ADB 与观察台的访问边界见[安全说明](docs/cn/SECURITY.md)。

## 开发状态与反馈

本项目由维护者与 Codex 通过 vibe coding 协作开发。目前已跑通连接、语音问答、录音和通知等核心流程，但细节交互与异常处理仍可能存在逻辑错误。我们正在开展专项测试并持续迭代功能，欢迎感兴趣的朋友自行构建、尝试开发和交流。

长录音与五分钟边界、突发通知排队、长期耗电、杀进程或重启后的恢复仍需完善测试；其他通知应用也需要分别验证。眼镜固件、原生 Launcher 和任意原生界面绘制不在当前功能范围内。具体测试结果见[测试记录](docs/cn/AUDIT.md)，功能变化见[变更记录](docs/cn/CHANGELOG.md)。

遇到 Bug、文档遗漏或有功能建议，欢迎提交 [Issue](https://github.com/aixleo66/aixleo-io-android/issues)，也可以通过你已有的维护者联系方式交流。请附版本或提交号、设备与系统信息、复现步骤及脱敏日志，不要上传 Key、录音、完整通知或其他个人数据。

下一步计划逐步分离连接、会话、录音、显示和模型适配接口，方便在其他 Android 项目中复用。
